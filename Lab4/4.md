# Лабораторна робота №4: Побудова багаторівневої архітектури серверного застосунку

## 1. Мета роботи

Розширити функціонал серверного застосунку за допомогою **багаторівневої архітектури** (Layered Architecture). Чітко розділити відповідальність компонентів на рівні `Router`, `Controller`, `Service`, `Repository` та `DataStore`. Реалізувати ізоляцію сервісу від конкретної бази даних за допомогою **Go interface**, додати централізовану обробку помилок, валідацію вхідних даних, middleware для логування запитів, а також покрити рівні `Service` модульними тестами.

---

## 2. Архітектура застосунку

Архітектура побудована за принципом однонаправленого потоку залежностей (Separation of Concerns):

```
HTTP Request 
   ↓
Router (маршрутизація, підключення middleware)
   ↓
Controller (парсинг HTTP, валідація, формування кодів відповіді)
   ↓
Service (бізнес-логіка, незалежна від HTTP)
   ↓
Repository Interface (абстракція доступу до даних)
   ↓
InMemoryRepository / DatabaseRepository (конкретна реалізація сховища)
```

- **Router**: Визначає HTTP-ендпойнти, методи та підключає middleware логування. Не містить бізнес-логіки.
- **Controller**: Отримує HTTP-запит, парсить JSON, здійснює базову валідацію, викликає методи сервісу та перетворює помилки бізнес-логіки у відповідні HTTP-статуси (`400 Bad Request`, `404 Not Found`, `409 Conflict`, `500 Internal Server Error`).
- **Service**: Містить чисту бізнес-логіку застосунку. Повністю ізольований від HTTP-контексту (не знає про `http.ResponseWriter` чи `http.Request`).
- **Repository**: Приховує деталі зберігання даних за інтерфейсом `UserRepository`, що дозволяє легко замінювати `InMemory` сховище на реальну БД (`PostgreSQL`, `MongoDB`) без зміни бізнес-логіки сервісу.

## 4. Основні лістинги коду

### 4.1. Інтерфейс репозиторію (`internal/repository/user.go`)
```go
package repository

import (
	"errors"
	"lab4/internal/model"
	"sync"
)

type UserRepository interface {
	Create(user model.User) (model.User, error)
	FindAll() ([]model.User, error)
	FindByID(id int) (model.User, error)
	Update(user model.User) (model.User, error)
	Delete(id int) error
}

type InMemoryUserRepository struct {
	mu     sync.RWMutex
	users  map[int]model.User
	nextID int
}

func NewInMemoryUserRepository() *InMemoryUserRepository {
	return &InMemoryUserRepository{
		users:  make(map[int]model.User),
		nextID: 1,
	}
}

func (r *InMemoryUserRepository) Create(user model.User) (model.User, error) {
	r.mu.Lock()
	defer r.mu.Unlock()

	for _, u := range r.users {
		if u.Email == user.Email {
			return model.User{}, errors.New("conflict: user with this email already exists")
		}
	}

	user.ID = r.nextID
	r.nextID++
	r.users[user.ID] = user
	return user, nil
}

func (r *InMemoryUserRepository) FindAll() ([]model.User, error) {
	r.mu.RLock()
	defer r.mu.RUnlock()

	users := make([]model.User, 0, len(r.users))
	for _, u := range r.users {
		users = append(users, u)
	}
	return users, nil
}

func (r *InMemoryUserRepository) FindByID(id int) (model.User, error) {
	r.mu.RLock()
	defer r.mu.RUnlock()

	user, exists := r.users[id]
	if !exists {
		return model.User{}, errors.New("not_found: user not found")
	}
	return user, nil
}

func (r *InMemoryUserRepository) Update(user model.User) (model.User, error) {
	r.mu.Lock()
	defer r.mu.Unlock()

	if _, exists := r.users[user.ID]; !exists {
		return model.User{}, errors.New("not_found: user not found")
	}
	r.users[user.ID] = user
	return user, nil
}

func (r *InMemoryUserRepository) Delete(id int) error {
	r.mu.Lock()
	defer r.mu.Unlock()

	if _, exists := r.users[id]; !exists {
		return errors.New("not_found: user not found")
	}
	delete(r.users, id)
	return nil
}
```

### 4.2. Logging Middleware (`internal/middleware/logging.go`)
Фіксує HTTP-метод, шлях, статус-код відповіді та час виконання запиту:
```go
package middleware

import (
	"log"
	"net/http"
	"time"
)

type responseRecorder struct {
	http.ResponseWriter
	status int
}

func (rec *responseRecorder) WriteHeader(code int) {
	rec.status = code
	rec.ResponseWriter.WriteHeader(code)
}

func LoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		recorder := &responseRecorder{ResponseWriter: w, status: http.StatusOK}

		next.ServeHTTP(recorder, r)

		duration := time.Since(start)
		log.Printf("%s %s %d %v", r.Method, r.URL.Path, recorder.status, duration)
	})
}
```

## 5. Результати тестування

### 5.1. Тестування API ендпойнтів (`Invoke-RestMethod`)

1. **Створення користувача (`POST /api/users`):**
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:8080/api/users" -Method Post -Body '{"name":"John Doe","email":"john@example.com"}' -ContentType "application/json"
   ```
   *Результат:* Статус `201 Created`. Повернено JSON: `{"id":1, "name":"John Doe", "email":"john@example.com"}`.

2. **Отримання списку користувачів (`GET /api/users`):**
   *Результат:* Статус `200 OK`. Повернено масив користувачів.

3. **Отримання користувача за ID (`GET /api/users/1`):**
   *Результат:* Статус `200 OK`. Користувача знайдено успішно.

4. **Перевірка стану здоров'я (`GET /health`):**
   *Результат:* Статус `200 OK`, повернено мікротаймстамп та статус сервісу.
