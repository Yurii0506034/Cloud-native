# Лабораторна робота №2: Дослідження моделей конкурентності та планування обчислень у Node.js та Go

## 1. Мета роботи
Дослідити моделі конкурентності та особливості планування обчислень у середовищах виконання **Node.js** та **Go**. Реалізувати та протестувати спеціалізовані ендпойнти для асинхронних операцій вводу-виводу (`/io`) й важких обчислювальних задач (`/cpu`), а також порівняти продуктивність і поведінку систем під час одночасних запитів.

---

## 2. Теоретичні відомості та архітектурний аналіз

### 2.1. Модель конкурентності в Node.js
Node.js використовує однопотокову модель виконання на базі асинхронного циклу подій (**Event Loop**, реалізованого через бібліотеку *libuv*). 
* **I/O операції (`/io`)**: Виконуються асинхронно на рівні операційної системи або у пул-потоків *libuv*, не блокуючи головний потік. Завдяки цьому велика кількість одночасних неблокуючих запитів обробляється дуже ефективно.
* **CPU-операції (`/cpu`)**: Синхронні математичні чи обчислювальні цикли виконуються безпосередньо в головному потоці JavaScript. Це призводить до **блокування Event Loop** — інші вхідні запити (наприклад, `/health`) змушені чекати завершення виконання важких обчислень, що демонструє слабке місце однопотокової архітектури для CPU-bound завдань.

### 2.2. Модель конкурентності в Go
Go реалізує модель конкурентності на базі **Green Threads** (зелених потоків) — **горутин (goroutines)**, які управляються внутрішнім планувальником Go (Go Scheduler) за алгоритмом *M:N* (де $M$ системних потоків обслуговують $N$ горутин).
* **I/O операції (`/io`)**: Імітуються через стандартну затримку (`time.Sleep`), при цьому планувач автоматично перемикає контекст на інші активні горутини.
* **CPU-операції (`/cpu`)**: У роботі реалізовано дві версії — послідовна (`cpu-sequential`) та паралельна (`cpu-parallel`, що розподіляє обчислення у кілька окремих горутин із синхронізацією через `sync.WaitGroup`). Паралельний підхід дозволяє ефективно задіяти всі ядра процесора, тоді як запити типу `/health` продовжують оброблятися паралельно й миттєво без блокування.

## 3. Реалізація сервісів

### 3.1. Node.js сервіс (`node-service/server.js`)
Додаток реалізовано на базі фреймворку Express з додаванням ендпойнтів `/io` та `/cpu`:

```javascript
const express = require('express');
const app = express();
const PORT = process.env.PORT || 3000;

app.use(express.json());

let items = {
    1: { id: 1, name: 'Laptop', price: 1200 },
    2: { id: 2, name: 'Mechanical Keyboard', price: 150 }
};
let nextId = 3;

// Health check
app.get('/health', (req, res) => {
    res.status(200).json({ status: 'OK', service: 'node-service', timestamp: new Date().toISOString() });
});

// Асинхронна I/O операція (/io)
app.get('/io', (req, res) => {
    const delay = parseInt(req.query.delay) || 100;
    setTimeout(() => {
        res.status(200).json({
            service: 'node-service',
            type: 'I/O operation',
            delayMs: delay,
            timestamp: new Date().toISOString()
        });
    }, delay);
});

// Важка обчислювальна CPU операція (/cpu) — блокує Event Loop
app.get('/cpu', (req, res) => {
    const iterations = parseInt(req.query.iterations) || 500000000;
    let counter = 0;
    for (let i = 0; i < iterations; i++) {
        counter++;
    }
    res.status(200).json({
        service: 'node-service',
        type: 'CPU-bound operation',
        iterations: iterations,
        result: counter,
        timestamp: new Date().toISOString()
    });
});

app.listen(PORT, () => {
    console.log(`Node.js service is running on http://localhost:${PORT}`);
});
```

### 3.2. Go сервіс (`go-service/main.go`)
Сервіс написано за допомогою стандартного пакета `net/http` з підтримкою послідовних та паралельних обчислень у горутинах:

```go
package main

import (
	"encoding/json"
	"net/http"
	"strconv"
	"sync"
	"time"
)

func main() {
	mux := http.NewServeMux()

	mux.HandleFunc("/health", healthHandler)
	mux.HandleFunc("/io", ioHandler)
	mux.HandleFunc("/cpu-sequential", cpuSequentialHandler)
	mux.HandleFunc("/cpu-parallel", cpuParallelHandler)

	println("Go service is running on http://localhost:8080")
	http.ListenAndServe(":8080", mux)
}

func healthHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]interface{}{
		"status":    "OK",
		"service":   "go-service",
		"timestamp": time.Now().Format(time.RFC3339),
	})
}

func ioHandler(w http.ResponseWriter, r *http.Request) {
	delayMs := 50
	if val := r.URL.Query().Get("delay"); val != "" {
		if d, err := strconv.Atoi(val); err == nil {
			delayMs = d
		}
	}
	time.Sleep(time.Duration(delayMs) * time.Millisecond)

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]interface{}{
		"service":   "go-service",
		"type":      "I/O operation",
		"delayMs":   delayMs,
		"timestamp": time.Now().Format(time.RFC3339),
	})
}

func cpuSequentialHandler(w http.ResponseWriter, r *http.Request) {
	tasks := 4
	iterations := 200000000
	var totalCounter int64 = 0

	for t := 0; t < tasks; t++ {
		var localCounter int64 = 0
		for i := 0; i < iterations; i++ {
			localCounter++
		}
		totalCounter += localCounter
	}

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]interface{}{
		"service": "go-service",
		"type":    "CPU Sequential",
		"result":  totalCounter,
	})
}

func cpuParallelHandler(w http.ResponseWriter, r *http.Request) {
	tasks := 4
	iterations := 200000000
	var wg sync.WaitGroup
	var totalCounter int64 = 0
	var muCounter sync.Mutex

	for t := 0; t < tasks; t++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			var localCounter int64 = 0
			for i := 0; i < iterations; i++ {
				localCounter++
			}
			muCounter.Lock()
			totalCounter += localCounter
			muCounter.Unlock()
		}()
	}
	wg.Wait()

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Execute(map[string]interface{}{
		"service": "go-service",
		"type":    "CPU Parallel (Goroutines)",
		"result":  totalCounter,
	})
}
```

## 4. Результати тестування та вимірювань

### 4.1. Експеримент із блокуванням
* **Node.js**: При надходженні фонового важкого запиту (`/cpu`) та паралельному виконанні `/health`, запит на `/health` очікував завершення обчислень через блокування єдиного потоку Node.js.
* **Go**: При паралельному виконанні обчислень через горутини (`/cpu-parallel`) запит на `/health` відповів миттєво (`status: "OK"` із актуальним мікротаймстампом), що підтверджує ефективність планувальника Go.

### 4.2. Результати замірів часу (`Measure-Command` у PowerShell)
1. **Go I/O (delay = 50ms):** Загальний час виконання склав `72.03 ms`.
2. **Go CPU Sequential:** Час виконання послідовних циклів склав `236.55 ms`.
3. **Go CPU Parallel (Goroutines):** Завдяки паралельному виконанню час зменшився до `89.22 ms`.
