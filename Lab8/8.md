# Звіт до Лабораторної роботи №8
## Масштабування за віссю X: reverse proxy Nginx, балансування навантаження та розгортання групи сервісів Node.js і Go у docker-compose

---

### 1. Мета роботи
Розгорнути сервіси з лабораторних робіт №4–7 як групу взаємозамінних безстатусних реплік за спільним зворотним проксі **Nginx**. Контейнеризувати артефакти збірки за схемою multi-stage (обфускація Node.js та стріпінг бінарника Go), налаштувати балансування трафіку між копіями (Least Connections, Round Robin, IP Hash для WebSocket), пасивні та активні health checks, failover, кешування статичних активів та відповідей проксі, буферизацію, таймаути, rate limiting на периметрі та SSL Termination, залишаючи бізнес-логіку рівнів `Service` та `Repository` без змін.

### 3. Контейнеризація та захист артефактів (Multi-stage Dockerfiles)

* **Node.js (`node-service/Dockerfile`)**:
  * Етап `build`: встановлення всіх залежностей (`npm ci`), обфускація вихідного коду за допомогою `javascript-obfuscator` у директорію `dist/` (`--control-flow-flattening`, `--dead-code-injection`, `--string-array-encoding base64`, `--self-defending`) та видалення dev-залежностей (`npm prune --omit=dev`).
  * Етап `runtime`: чистий образ `node:20-alpine`, куди копіюються лише production `node_modules` та зобфускований `dist/`. Вихідний код `src/` в образ не потрапляє. Контейнер запускається від непривілейованого користувача `USER node`.
* **Go (`go-service/Dockerfile`)**:
  * Етап `build`: статична компіляція бінарника зі стріпінгом таблиці символів та налагоджувальної інформації (`CGO_ENABLED=0 go build -ldflags="-s -w" -trimpath -o bin/app ./cmd/server`).
  * Етап `runtime`: мінімальний образ `alpine:3.20` з єдиним виконуваним файлом `/app/app`, запущеним від непривілейованого користувача `USER appuser`.
* **Ізоляція мережі та секретів**: Файли `.env` виключені через `.dockerignore` і передаються в контейнери виключно під час запуску через секцію `environment` у `docker-compose.yml`. Усі сервіси (`node-app-1..3`, `go-app`, `postgres`, `mongo`) використовують директиву `expose` замість `ports`, що робить їх недосяжними ззовні хоста.

### 4. Конфігурація Nginx та алгоритми балансування (`nginx/nginx.conf`)

1. **Алгоритми балансування навантаження**:
   * **Least Connections (`least_conn`)** для `node_backend` (`node-app-1..3`) — спрямовує нові запити на репліку з найменшою кількістю активних з'єднань.
   * **Round Robin** для `go_backend` (`go-app`) — рівномірний розподіл однорідних запитів звітів (`/api/reports`).
   * **IP Hash (`ip_hash`)** для `ws_backend` (`/ws`) — закріплює клієнта за конкретною копією на весь час життя довгоживучого WebSocket-з'єднання, передаючи заголовки `Upgrade` та `Connection "upgrade"` з таймаутом `proxy_read_timeout 600s`.
2. **Відмовостійкість (Health Checks та Failover)**:
   * Налаштовані пасивні перевірки `max_fails=3 fail_timeout=30s` для кожної репліки.
   * Директива `proxy_next_upstream error timeout http_502 http_503 http_504` автоматично повторює помилковий запит на наступному справному інстансі без розриву клієнтського з'єднання.
   * Активні перевірки реалізовані в `docker-compose.yml` через періодичне опитування ендпоінта `/health`.
3. **Кешування та буферизація**:
   * Статичні файли за маршрутом `/static/` віддаються безпосередньо Nginx з диска із заголовками `expires 30d` та `Cache-Control: "public, immutable"`.
   * Налаштовано зону кешування проксі (`proxy_cache_path`) та увімкнено буферизацію відповідей (`proxy_buffering on`) для захисту event loop воркерів від повільних клієнтів.
4. **Rate Limiting на периметрі**:
   * Загальний ліміт для `/api/`: $10\text{ r/s}$ (`burst=20 nodelay`) та обмеження паралельних з'єднань `limit_conn 20`.
   * Жорсткий ліміт проти брутфорсу для `/api/auth/login`: $1\text{ r/s}$ (`burst=5 nodelay`), що централізовано захищає весь флот реплік.
5. **SSL Termination**:
   * Згенеровано самопідписаний TLS-сертифікат (`CN=localhost`, термін дії 365 днів).
   * Увесь HTTP-трафік із порту `80` перенаправляється постійним редиректом (`301`) на HTTPS (`443`).
   * Дозволені лише сучасні протоколи `TLSv1.2` та `TLSv1.3`, додано заголовок безпеки `Strict-Transport-Security` (HSTS), а бекендам передається реальна схема та IP клієнта (`X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`).

* **Ізоляція портів**: Назовні відкриті виключно порти `80` та `443` контейнера `lab8-nginx-1`. Прямий доступ до баз даних та реплік застосунків ззовні мережі Docker заблокований.
* **Взаємозамінність реплік**: Завдяки безстатусній JWT-автентифікації та спільному сховищу даних усі три репліки Node.js (`node-app-1..3`) взаємозамінні та обробляють запити без необхідності використання sticky sessions для REST API.

### 6. Висновки
У ході лабораторної роботи успішно реалізовано горизонтальне масштабування мікросервісного застосунку за віссю X. Застосування multi-stage контейнерів забезпечило мінімальний розмір образів і захист скомпільованих артефактів. Впровадження Nginx як єдиного зворотного проксі дозволило централізувати SSL Termination, захист периметра від перевантажень і брутфорсу, кешування, балансування трафіку за різними алгоритмами та автоматичне відновлення при відмовах окремих реплік без зміни бізнес-коду сервісів.
